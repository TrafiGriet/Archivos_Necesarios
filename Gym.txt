Sistema de gestion de un gym

Funcionalidades (puede variar, se pueden sumar más o se pueden quitar/modificar algunas):

Todos los usuarios deben iniciar sesion para poder así utilizar dichas funcionalidades exclusivas de su rol.
Alumno: Usuario final. 
* Ver su rutina actual.
* Ver sus datos personales (perfil).
* Ver el estado de su cuota (pagada, vencida, próxima a vencer) / Consultar plan de gimnasio.
* Descargar su ficha médica (si tiene permisos) o Ver sus datos médicos registrados.
* Ver historial de pagos.
* Ver su asistencia.

Profesor: Responsable del seguimiento de alumnos.
* Ver los alumnos asignados.
* Crear y modificar rutinas.
* Ver datos personales junto a la ficha médica de cada alumno.
* Registrar asistencia.
* Ver qué alumnos entrenan en su turno.

El dueño (Admin General) no quiere que el recepcionista (Admin Gestión) le vea la facturación, pero necesita que le cobre a los alumnos y maneje los turnos.
Administrador general: usuario con permisos administrativos completos. Además de las operaciones disponibles para el administrador de gestión, puede gestionar profesores y planes, así como acceder a estadísticas e información financiera del gimnasio.
ADMIN_GENERAL
├── gestionar alumnos       ✅
├── gestionar profesores    ✅
├── gestionar pagos         ✅
├── gestionar planes        ✅
├── gestionar turnos        ✅
├── ver estadísticas        ✅
└── ver ingresos            ✅

Administrador de gestión: usuario encargado de las operaciones administrativas habituales del gimnasio, como la gestión de alumnos, pagos y turnos.
ADMIN_GESTION
├── gestionar alumnos       ✅
├── gestionar profesores    ❌
├── gestionar pagos         ✅
├── gestionar planes        ❌
├── gestionar turnos        ✅
├── ver estadísticas        ❌
└── ver ingresos            ❌

Posible modelo:

ROL   --> represetna los permisos que tiene cada usuario
──────────────── 
id
nombre  ---> los roles iniciales son: alumno, profesor, admin_gestion y admin_general; dodne cada usuario tiene un rol.


USUARIO --> representa a cualquier persona que utiliza el sistema.
────────────────
id
email
password_hash
nombre
apellido
dni
telefono
estado  
rol_id  --> fk de rol


FICHA_MEDICA
────────────────
id
alumno_id --> fk de usuario + unique.
object_key_minio
observaciones
fecha_actualizacion

Un alumno puede tener como máximo una ficha médica, USUARIO (ALUMNO) 1 ───── 1 FICHA_MEDICA

PLAN --> planes que ofrece el gim.
────────────────
id
nombre
descripcion
precio_mensual
estado

PLAN 1 ───── N PAGO


PAGO --> pago de la cuota mensual.
────────────────
id
alumno_id --> fk de usuario 
plan_id  --> fk de plan
monto_abonado
fecha_pago
fecha_vencimiento

El alumno puede tener muchos pagos históricos.
Alumno 1 --------- N Pagos
Plan 1 ----------- N Pagos
No se almacenaría "estado" en "Pago" porque se puede determinar si esta vencido o vigente utilizando las fechas.

EJERCICIO --> catalogo de ejercicios disponibles.
────────────────
id
nombre
grupo_muscular
descripcion
object_key_minio

La imagen sería almacenada en MinIO, mientras que en MySQL guardamos la referencia

RUTINA --> Representa una rutina creada para un alumno.
────────────────
id

profesor_id --> fk de usuario
nombre
fecha_creacion
activa


RUTINA_EJERCICIO --> relaciona rutinas con ejercicios.
────────────────
id
rutina_id --> fk de rutina

series
repeticiones

TURNO --> horario de entrenamiento organizado por un profe.
────────────────
id
profesor_id --> fk de usuario.
dia_semana
hora_inicio
hora_fin

Un profesor puede estar asociado a varios turnos. Un turno pertenece a un único profesor.

Un alumno puede estar asociado a varios turnos y un turno puede tener varios alumnos. Esta relación N:M se resuelve mediante la entidad ALUMNO_TURNO.

ALUMNO_TURNO
────────────────
id
alumno_id --> fk de usuario
turno_id --> fk de turno

Se podría agregar una restricción como UNIQUE(alumno_id, turno_id) para evitar que un alumno sea asignado dos veces al mismo turno.


ASISTENCIA --> registra la asistencia de un alumno.
────────────────
id
alumno_id --> fk de usuario
registrado_por --> fk de usuario
fecha
hora
